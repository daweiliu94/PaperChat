# Install PaperChat with Codex

Use the prebuilt [v0.1.4 release](https://github.com/daweiliu94/PaperChat/releases/tag/v0.1.4). Ordinary installation does not require cloning the source, installing dependencies, Xcode or a signing certificate. Source code is available under MIT for users who want to modify it. This package supports Safari; see [CODEX_CHROME.md](CODEX_CHROME.md) for a separate Chrome generation task.

1. **Check compatibility and choose a destination.** Require an Apple Silicon Mac and macOS 14+ for the native app. Use current Safari; the original live tests used Safari 27. Safari below 26.4 is unsupported, and older-than-tested versions still need beta testing. Help the user update Safari before proceeding if necessary. Follow the user's workspace instructions and save downloaded artifacts in a durable PaperChat project directory.
2. **Download and verify.** Download `PaperChat-0.1.4-macOS-arm64.zip` and `SHA256SUMS` from the v0.1.4 release. Verify the ZIP's SHA-256 value against the checksum file before extracting it; the expected value is `56cd4209365adffe910c5f0b01d3f9f2e9ed2562a7ec4dbf000e1ffd51c030b2`. For authenticated GitHub CLI users, `gh release download v0.1.4 --repo daweiliu94/PaperChat --pattern 'PaperChat-0.1.4-macOS-arm64.zip' --pattern SHA256SUMS --dir <destination>` downloads both. The public release can also be downloaded in a browser without a GitHub account.
3. **Inspect the app and install.** Create disposable local staging with `mktemp -d -t PaperChatInstall`, then extract with `ditto -x -k <zip> <staging-directory>`. Keep staging outside cloud-synced Documents/Desktop folders: file providers can add Finder metadata that breaks signature verification. Confirm bundle IDs `local.paperchat.PaperChat` and `local.paperchat.PaperChat.Extension`, version 0.1.4/build 5, and successful `codesign --verify --deep --strict <staging-directory>/PaperChat.app`. Install the whole app at `/Applications/PaperChat.app`, preserving its signed bytes and quarantine metadata, then verify its signature again at the installed path. Retain the downloaded ZIP, which includes `THIRD_PARTY_NOTICES.txt` and the bundled font sources alongside the app. If an installed copy already exists, obtain replacement approval, confirm it is idle and retain a rollback copy first. Keep the user's histories, bookmarks, preferences and Keychain untouched. Do not re-sign the downloaded package; app and extension authenticate each other's original signatures.
4. **Register the extension.** Register the containing app with LaunchServices and the exact embedded extension with PlugInKit. The commands are `/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f /Applications/PaperChat.app` and `/usr/bin/pluginkit -a '/Applications/PaperChat.app/Contents/PlugIns/PaperChat Extension.appex'`. If duplicate registrations prevent invocation, remove and re-add only that exact extension path. Verify one registration with `pluginkit -m -A -D -v -i local.paperchat.PaperChat.Extension`.
5. **Help the user enable it.** This development beta is not notarized. Let the user complete any macOS Privacy & Security approval and any authorization required by your tools. Preserve Gatekeeper and quarantine protections. In Safari, enable Settings → Advanced → Show features for web developers, then Settings → Developer → Allow unsigned extensions, and enable PaperChat under Extensions. Older Safari versions put Allow Unsigned Extensions in the Develop menu. Safari resets this development setting when it quits. Grant page access when invoking PaperChat as needed.
6. **Set up the user's own data and account.** Open an article in Safari, click the PaperChat toolbar button, then **Chat options (⋯) → Setup**. This explicit action opens the otherwise quiet helper's configuration window. Create or reuse a durable history project on this Mac and select its root folder; PaperChat creates `history/` underneath. The beta's folder-picker example refers to the original development project; choose the user's own directory. Let the user complete Continue with ChatGPT and consent in their browser using their own eligible account. Tokens remain in their Keychain. Close Setup when finished.
7. **Confirm readiness.** Reopen the sidebar if necessary and confirm the model menu loads and Paper ready appears. Use a synthetic local article/PDF for an optional smoke test. Summarize registration and readiness without printing account details, tokens or conversation contents. Normal helper startup should remain quiet.

If download, checksum or signature verification fails, stop and report it. If Safari does not show the extension, inspect only PaperChat's registration and the relevant settings before retrying. If the toolbar does nothing after an update, wait until any active reply has stopped, turn only PaperChat off and back on under Safari → Settings → Extensions, then reload the article and retry. Re-enabling resolved a retained-context incident during local testing; it is a recovery step, not a code fix in this release. A certificate or signature failure needs a fresh owner-provided package, rather than weakening the app's peer checks. Account eligibility and plan limits are enforced by ChatGPT.

Apple documents [Safari beta installation](https://developer.apple.com/documentation/safariservices/running-your-safari-web-extension) and [extension distribution](https://developer.apple.com/documentation/safariservices/distributing-your-safari-web-extension).
